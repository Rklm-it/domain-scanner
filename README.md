# domain-scanner

Проверка доменов перед заливом: ищет ту историю и те косяки в настройке, из-за
которых Google выкидывает аккаунт на верификацию.

Идея простая. Ты заливаешь пять одинаковых связок с пяти аккаунтов, три живут
неделями, две улетают на верификацию за день. Креативы те же, офер тот же —
значит разница в доменах. Сканер вытаскивает то, что Google видит о домене
снаружи, и показывает, чем «плохие» домены отличаются от «хороших».

```
$ domain-scanner -f domains.txt --footprint

lucky-cash-now.top  —  87/100  AVOID
  [#################...]  Do not put spend behind this domain.
  XX re-registered domain with a prior life in a flagged vertical (2014–2019): "Lucky Star Casino"
   X no privacy policy, terms or contact page — the exact gap that sends an account into business verification
   ! .top is a tier-3 TLD (high abuse rate)
   ! 2 hyphens in the name

northwind-shop.com  —  12/100  CLEAN
  [##..................]  No meaningful red flags found.
   ~ registered 8mo ago — under a year old
```

---

## Установка

```bash
git clone <repo> && cd domain-scanner
pip install -r requirements.txt

python -m domain_scanner example.com
# либо поставить как команду:
pip install -e .
domain-scanner example.com
```

Нужен Python 3.10+. Зависимости всего две: `requests` и `dnspython`.

## Быстрый старт

```bash
# один домен
domain-scanner mydomain.com

# пачка из файла + анализ общего следа + CSV для таблицы
domain-scanner -f domains.txt --footprint --csv report.csv

# только история домена (быстро, без запросов к самому сайту)
domain-scanner mydomain.com --only rdap,wayback,crtsh

# подробный вывод: info-находки, сырые данные, тайминги по каждой проверке
domain-scanner mydomain.com -v
```

`domains.txt` — по домену на строку. Можно кидать URL целиком, с `www.`, с
путём, через запятую, с комментариями через `#` — всё нормализуется:

```
https://www.lucky-cash-now.top/lp1?utm=x   # старый, улетел на верифу
northwind-shop.com
another-lander.xyz
```

## Что именно проверяется

`domain-scanner --list-checks` покажет актуальный список. По группам:

### История домена — главное

| Проверка | Что смотрит |
| --- | --- |
| `rdap` | Дата регистрации, регистратор, срок оплаты, EPP-статусы |
| `wayback` | Архив archive.org: что было на домене раньше |
| `crtsh` | Certificate Transparency: когда домен реально впервые ожил |

**Это то, ради чего всё писалось.** Типовой сценарий, который жжёт байеров:
домен зарегистрирован месяц назад, а в архиве у него контент с 2014 года.
Значит его уже использовали, бросили, и ты купил его на дропе. Репутация
привязана к имени, а не к твоей регистрации — и Google это помнит.

Сканер это ловит: сравнивает дату регистрации из RDAP с первым снимком в
archive.org и с первым сертификатом в CT-логах. Если история старше регистрации
больше чем на полгода — домен переиспользованный. Дальше он вытягивает `<title>`
старых страниц и говорит, чем домен был занят: казино, фарма, дейтинг, или
просто парковка.

Дата регистрации переписывается при перерегистрации. Первый сертификат в
CT-логах — нет. Поэтому проверок три, а не одна.

### Репутация

| Проверка | Что смотрит |
| --- | --- |
| `blocklists` | Spamhaus DBL, SURBL, URIBL, SEM — по DNS, без ключей |
| `safebrowsing` | Google Safe Browsing v4 — **нужен бесплатный ключ** |
| `virustotal` | ~90 антивирусных вендоров + категории — нужен бесплатный ключ |

Safe Browsing — единственный источник здесь, который буквально показывает мнение
самого Google о домене. Ключ бесплатный, поставить стоит.

### Инфраструктура

| Проверка | Что смотрит |
| --- | --- |
| `dns` | A/NS/MX/SPF/DMARC, парковочные NS, бесплатный хостинг |
| `hosting` | ASN и владелец сети (Team Cymru), соседи по IP |

Отсутствие MX/SPF/DMARC — слабый сигнал сам по себе, но именно по нему отличают
работающий бизнес от чистого ленда. Триста доменов на одном IP — ты наследуешь
репутацию соседей.

### Сам сайт

| Проверка | Что смотрит |
| --- | --- |
| `http` | Отдаётся ли страница, редиректы, TLS, тонкий контент, страницы политик |
| `cloaking` | Одинаковый ли контент для браузера, Googlebot и AdsBot |
| `tld` | Уровень абуза зоны |
| `naming` | Бренды в имени, тайпсквоттинг, дефисы, мусорные слова |

Отсутствие privacy policy / terms / contact — самая частая причина, по которой
аккаунт уезжает на верификацию бизнеса. Проверка ищет эти ссылки на русском,
английском, немецком, испанском, польском и турецком.

`cloaking` — диагностика: сканер тянет страницу под UA браузера, Googlebot и
AdsBot-Google и сравнивает видимый текст. Если контент разный — это ровно тот
паттерн, на который срабатывает автоматика Google. Полезно прогонять по своим же
доменам перед масштабированием.

## Общий след по пачке (`--footprint`)

Отдельно от оценок каждого домена. Ищет, чем домены в пачке похожи друг на
друга:

```
Shared footprint across the batch
   X 5/5 domains resolve to the same IP 45.11.22.33
       a.com, b.com, c.com, d.com, e.com
   X 5/5 domains share the tracking ID google_analytics:G-ABCD1234
       a.com, b.com, c.com, d.com, e.com
   ! 4/5 domains were registered on the same day (2026-07-14)
       a.com, b.com, c.com, d.com
```

Вот это, скорее всего, и есть ответ на твой вопрос. Каждый домен по отдельности
может быть чистым, но если все пять сидят на одном IP, куплены в один день у
одного регистратора и отдают побайтово одинаковый ленд с одним GA-счётчиком — то
снаружи это одна и та же операция. Как только один попадает под раздачу,
остальные подтягиваются.

Что ищется: общий IP, ASN, NS-оператор, регистратор, дата регистрации, хеш
видимого текста страницы, `<title>`, ID счётчиков (GA, GTM, Google Ads, FB
Pixel, TikTok).

## Оценка и вердикт

Каждая находка имеет вес: `low` 5, `medium` 12, `high` 22, `critical` 35. Веса
складываются, потолок 100. Одна тяжёлая находка не размывается кучей чистых
проверок: `critical` поднимает счёт минимум до 75, `high` — до 45.

| Счёт | Вердикт | Смысл |
| --- | --- | --- |
| 0–19 | `CLEAN` | Красных флагов нет |
| 20–39 | `WATCH` | Дисквалифицирующего нет, но не идеально |
| 40–69 | `RISKY` | Можно, если сначала починить перечисленное |
| 70+ | `AVOID` | Не лить |
| — | `UNREGISTERED` | Домен не зарегистрирован, оценивать нечего |

Ниже вердикта — строка `confidence`. Это доля проверок, которые реально дали
данные. Если крупные источники не ответили — вердикт помечается как
провизорный. `CLEAN` при 40% покрытия означает «не нашли», а не «чисто».

Коды выхода: `0` — все чисто, `1` — хотя бы один домен набрал `--fail-over`
(по умолчанию 40) или больше, `2` — ошибка ввода. Удобно для CI или скрипта,
который прогоняет свежекупленные домены.

## Ключи API

Всё работает без ключей. С ключами — заметно точнее. Скопируй `.env.example`
в `.env` и заполни, что есть:

```bash
cp .env.example .env
```

| Переменная | Зачем | Лимит |
| --- | --- | --- |
| `GOOGLE_SAFE_BROWSING_API_KEY` | Мнение самого Google о домене | бесплатно, щедрый |
| `VIRUSTOTAL_API_KEY` | ~90 вендоров + категории | 4 запроса/мин (соблюдается автоматически) |

Проверка без своего ключа не падает, а помечается как `skipped` и не портит
`confidence`.

## Про DNS-блоклисты — важно

Spamhaus, SURBL и URIBL **режут запросы с публичных резолверов** (8.8.8.8,
1.1.1.1). Если у тебя в системе прописан Google DNS, эти проверки будут молча
возвращать пустоту или отказ. Сканер это замечает и пишет предупреждение.

Лечится указанием резолвера провайдера или локального:

```bash
domain-scanner -f domains.txt --nameserver 192.168.1.1
```

## Прочие флаги

```
-w, --workers N       сколько доменов параллельно (по умолчанию 8)
    --timeout SEC     таймаут HTTP
    --proxy URL       прокси для HTTP-проверок — посмотреть ленд из нужного гео
    --skip LIST       пропустить проверки: --skip cloaking,virustotal
    --only LIST       только эти проверки
    --json / --csv / --markdown PATH    выгрузка ('-' = stdout)
    --no-preflight    не проверять свою же связь перед сканом
```

Перед сканом сканер проверяет собственный интернет. Если исходящий HTTPS или DNS
не работают, он говорит об этом и пропускает соответствующие проверки — вместо
того чтобы записать все домены в «сайт не открывается».

## Глоссарий находок

Стабильные коды, по ним удобно грепать JSON.

### История

| Код | Значение |
| --- | --- |
| `wayback.recycled_suspect` | Перерегистрирован, раньше был в палёной вертикали — **худший сигнал** |
| `wayback.recycled` | Перерегистрирован, в архиве контент до текущей регистрации |
| `wayback.recycled_parked` | Перерегистрирован, но раньше была только парковка |
| `wayback.mostly_redirects` | История домена — сплошные редиректы (дорвей) |
| `crtsh.predates_registration` | Сертификаты старше текущей регистрации |
| `crtsh.just_went_live` | Первый сертификат выпущен на этой неделе |
| `crtsh.many_subdomains` | 40+ поддоменов в CT-логах |
| `rdap.brand_new` | Зарегистрирован меньше 30 дней назад |
| `rdap.young` | Меньше 90 дней |
| `rdap.expiring_soon` | Регистрация кончается в течение 60 дней |
| `rdap.bad_status` | Реестр повесил hold / pending delete |
| `rdap.abused_registrar` | Регистратор часто светится в абуз-отчётах |

### Репутация

| Код | Значение |
| --- | --- |
| `safebrowsing.flagged` | Google Safe Browsing помечает домен |
| `blocklist.listed` | В публичном блоклисте (спам/фишинг/малварь) |
| `blocklist.query_rejected` | Список отказал в запросе — смени резолвер |
| `virustotal.malicious` | 3+ вендора считают домен вредоносным |
| `virustotal.bad_reputation` | Плохая community-репутация |

### Сайт

| Код | Значение |
| --- | --- |
| `http.unreachable` | Не открывается ни по HTTPS, ни по HTTP |
| `http.client_error` / `http.server_error` | Отдаёт 4xx / 5xx |
| `http.no_trust_pages` | Нет ни политики, ни условий, ни контактов |
| `http.missing_trust_pages` | Часть страниц доверия отсутствует |
| `http.offsite_redirect` | Редиректит на другой домен |
| `http.js_offsite_redirect` | Уводит на другой домен джаваскриптом |
| `http.thin_content` | Почти нет видимого текста |
| `http.no_https` | HTTPS не работает |
| `http.tls_expired` | Сертификат просрочен |
| `cloaking.content_differs` | Googlebot/AdsBot видят не то же, что браузер |
| `cloaking.*_blocked` | Сайт не отвечает краулеру Google |

### Инфраструктура и имя

| Код | Значение |
| --- | --- |
| `dns.parked` | NS парковочного сервиса |
| `dns.no_address` | Делегирован, но ничего не хостится |
| `dns.free_hosting` | Бесплатный хостинг |
| `dns.no_mx` | Нет почты на домене |
| `hosting.crowded_ip` | 200+ доменов на одном IP |
| `hosting.suspect_network` | Сеть с тяжёлой историей абуза |
| `tld.high_abuse` | Зона третьего тира (.top, .xyz, .icu …) |
| `naming.brand_lookalike` | В имени чужой бренд |
| `naming.typosquat` | Отличается от бренда на 1–2 буквы |
| `naming.many_hyphens` | Три и больше дефисов |
| `naming.spammy_words` | Слова из мусорных воронок |

## Настройка под себя

Данные вынесены в JSON, правь под свои вертикали:

- `domain_scanner/data/tld_risk.json` — тиры зон
- `domain_scanner/data/keywords.json` — бренды, чувствительные слова, мусорные
  слова, и `brand_domains` (официальные домены брендов, чтобы `google.com` не
  считался подделкой под Google)
- `domain_scanner/data/registrars.json` — регистраторы, парковочные NS

Пороги (что считать «свежим» доменом, сколько соседей по IP это «много»)
лежат в `domain_scanner/config.py`.

Новая проверка — это функция с декоратором:

```python
from domain_scanner.checks.base import register, ScanContext
from domain_scanner.models import CheckResult

@register("mycheck", order=60, description="...", transport="http")
def check_mine(ctx: ScanContext) -> CheckResult:
    result = CheckResult(name="mycheck")
    result.add("mycheck.problem", "medium", "человекочитаемое описание")
    return result
```

Импортируй модуль в `domain_scanner/checks/__init__.py` — дальше он сам
подхватится в CLI, скоринг и все форматы вывода. `transport` (`none`/`dns`/
`http`) говорит, что делать, если этого транспорта нет.

## Честные оговорки

**Это эвристика, а не приговор Google.** Никакого доступа к внутренним сигналам
Google Ads нет ни у кого снаружи. Сканер собирает то, что видно публично, и
взвешивает по тому, что обычно коррелирует с проблемами. Домен с оценкой 0 может
улететь на верификацию, домен с 60 — прожить полгода.

**Веса подобраны руками, а не обучены на данных.** У тебя есть то, чего нет
здесь: история твоих собственных доменов. Прогони через сканер и те, что умерли,
и те, что живут, сравни находки — и подкрути веса под свою вертикаль. Для этого
`--json` и `--csv`.

**Верификация бывает не из-за домена.** Новый платёжный метод, резкий скачок
бюджета, гео аккаунта, вертикаль, возраст самого аккаунта — всё это триггерит
проверки независимо от домена. Сканер закрывает только доменную часть.
